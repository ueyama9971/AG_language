## セッション: 言語切替機能の実装 + 翻訳辞書拡充

### 実施内容

#### 1. 言語切替機能の設計・実装
- 設計書作成: `docs/superpowers/specs/2026-06-20-language-switcher-design.md`
- 実装計画: `docs/superpowers/plans/2026-06-21-language-switcher.md`
- superpowers:subagent-driven-development で実行

#### 2. 方式転換: 文字列直接置換 → DOM翻訳ランタイム注入
- **旧方式**: main.js内の英語文字列をPythonで直接日本語に置換
- **新方式**: main.js末尾にi18nランタイム（IIFE）を注入、DOMレベルで動的翻訳
- MutationObserverでReact再レンダリングを検知→即座に翻訳適用
- localStorage（key: `ag_lang`）で言語設定を永続化
- EN→JP: 即時DOM翻訳 / JP→EN: ページリロード（確実に英語に戻る）

#### 3. 言語トグルUI
- 画面左下にフローティングドロップダウン（🌐 English / 日本語）
- `position:fixed; bottom:12px; left:100px; z-index:99999`
- 設定アイコンと被らない位置に調整済み

#### 4. パッチスクリプト改修 (`apply_ja_patch_standalone.py`)
- `UI_TRANSLATIONS` / `UI_REGEX_TRANSLATIONS` / `apply_translations()` を削除
- `load_i18n_runtime()` / `inject_i18n_runtime()` を追加
- `validate_translations()` → JSの翻訳テーブルからキーを抽出して検証する方式に変更
- `check_patch_status()` → `ag_i18n_runtime` 署名文字列の存在で判定
- `--dry-run` にサイズチェック（margin表示）を追加

#### 6. --dry-run のmargin比較対象の注意点
- `--dry-run` は現在のバイナリの圧縮サイズと比較する
- パッチ済みバイナリで実行するとmarginが不正確になる（元の圧縮サイズより小さい値と比較するため）
- 正確な結果を得るには `--rollback` してから `--dry-run` を実行する

### 決定事項
- DOM翻訳方式を採用（元の英語を保持し、ランタイムでDOM書き換え）
- JP→EN切替はリロード方式（逆引き翻訳の不完全さを回避）
- 翻訳テーブルはi18n_runtime.jsに集約（Pythonスクリプト側には持たない）
- サイズ予算: 元の圧縮サイズ（2,245,769 bytes）以下であること
